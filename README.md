# Zepto Inventory Management System

This repository contains the complete data engineering, machine learning forecasting, and SQL-based KPI analytics pipeline for Zepto's Delhi dark store network. The system is designed to track daily inventory movements, forecast future demand using Machine Learning, and dynamically calculate critical supply chain metrics like Reorder Points, Safety Stock, and ABC Classifications.

---

## 🗄️ Database Schema & Overview

The underlying database (`zepto_inventory`) is structured into Base Tables (raw operational data), Derived Tables (analytical facts), and Views (real-time KPIs).

### 1. Initial Base Tables
These tables represent the core operational data generated by customers, suppliers, and store operations:
* `products`: Master data for all SKUs, including MRP, unit cost, perishability, and shelf life.
* `dark_stores`: Master data for Zepto fulfillment centers (locations, capacities).
* `suppliers`: Supplier master data including average lead times.
* `product_suppliers`: Mapping of which suppliers provide which SKUs and at what cost price.
* `customers`: Registered user data.
* `orders` & `order_items`: Transactional sales data linking customers, stores, and products.
* `purchase_orders`: Inbound stock replenishment orders from suppliers.

### 2. Derived Fact Tables
These tables are generated programmatically by data pipelines and machine learning scripts:
* `fact_ml_forecasts`: Contains the daily predicted demand (`predicted_demand`) generated by the Machine Learning model for each Store/SKU combination.

### 3. Core Analytical Views
Views that aggregate base data for downstream reporting:
* `view_inventory_snapshot`: A daily log of opening stock, total purchased, total sold, and closing stock for every SKU across every store.
* `view_daily_sales`: Aggregated daily sales and revenue metrics.
* `view_wastage_log`: Tracks expired perishable inventory.

## 📊 Key Performance Indicators (KPIs)

The system dynamically calculates the following advanced supply chain metrics entirely within SQL Views. 

| KPI Name | SQL View | Formula Used | Significance |
|----------|----------|--------------|--------------|
| **ABC Classification** | `view_abc_classification` | Category A: Top 70% of Cumulative Revenue<br>Category B: Next 20%<br>Category C: Bottom 10% | Helps prioritize high-value inventory. 'A' items require strict control and accurate forecasting. |
| **Sales Velocity (DSV)** | `view_sales_velocity` | `Total Sold Quantity / Number of Days Sold` | Measures how fast an item sells on average, forming the baseline for demand forecasting. |
| **Reorder Point (ROP)** | `view_reorder_points` | `(Lead Time * DSV) + Safety Stock` | The exact inventory level at which a new purchase order must be placed to prevent stockouts. |
| **Safety Stock** | `view_reorder_points` | `Z-Score(95%) * StdDev(Sales) * SQRT(Lead Time)` | Buffer stock kept to mitigate fluctuations in demand and supplier delivery delays. |
| **Inventory Turnover Ratio** | `view_inventory_turnover_doh` | `Total Cost of Goods Sold (COGS) / Average Inventory Value` | Indicates how efficiently inventory is being sold and replaced over a given period. |
| **Days on Hand (DOH)** | `view_inventory_turnover_doh` | `365 / Inventory Turnover Ratio` | Measures the average number of days inventory is held before being sold. Lower is better. |
| **Supplier Reliability** | `view_supplier_reliability` | `Actual Delivery Date - Expected Delivery Date` | Tracks supplier delays to adjust lead times and safety stock calculations. |
| **Stock-Out Incidents** | `view_stock_out_incidents` | Count of days where `closing_stock <= 0` while demand existed. | Identifies lost sales opportunities and poor replenishment cycles. |

## 🤖 Machine Learning Forecasting

To move beyond naive historical averages, this project utilizes a Machine Learning pipeline to predict future SKU demand. These predictions are fed back into the SQL layer to calculate dynamic Reorder Points.

### Data Engineering (`forecasting_features.sql`)
The pipeline extracts highly engineered time-series features directly from MySQL, including:
* 7-day, 14-day, and 30-day rolling sales averages.
* Day-of-week and month seasonality indicators.
* Lead time and price variance factors.

### Train/Test Split Strategy
The model utilizes a chronological time-series split to prevent data leakage:
* **Training Set:** Historical data spanning from the start of the dataset up to **February 28, 2025**. The model learns purchasing patterns, seasonal spikes, and velocity trends during this period.
* **Testing / Prediction Set:** Future predictions are generated for the month of **March 2025 (March 1 - March 31)**. 

The outputs for the prediction set are stored in `ml_predictions.csv` and loaded into the `fact_ml_forecasts` table, where the database automatically joins the ML predictions against real-time physical inventory to flag SKUs that need immediate reordering.
